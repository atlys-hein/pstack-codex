# Delegation details

Read this section before assigning or continuing native workers.

## Native subagent orchestration

This skill explicitly requests useful, bounded delegation for substantial work when native agents are available. Use the currently exposed collaboration tools in the Codex app, or the host's native agent tools when provided, following their actual schemas. Apply the shared model policy before every spawn. Do not guess agent types, model identifiers, effort parameters, concurrency limits, or isolation behavior. Use the contract's permitted models and default effort pairs; inherit only verified compliant settings. Use the [Poteto worker role](../../pstack/references/agents/poteto-agent.md) as a prompt brief for implementation delegates, not as a registered agent type.

The parent chooses the plan and accepts the result. Delegate independent research, a well-scoped implementation, or an independent verification pass. Keep the critical path moving while workers run. For a small, tightly coupled task, direct work can be faster and safer than spawning a worker. If agents are unavailable, perform the same steps serially and say which review separation was unavailable.

Every brief restates the user's goal and carries relevant current instructions, allowed paths, explicit exclusions, evidence pointers, acceptance criteria, permitted checks, and report shape. State whether the worker may write files. Workers return findings or a finished owned slice to the parent. They do not invoke this router, create user-facing chats, or delegate again unless the parent assigns a concrete nested scope and budget.

Native workers can share the parent's checkout. They are not isolated merely because they have different agent IDs. Give one writer each file or mutable resource. Use actual isolated worktrees for competing implementations or conflicting ownership, and validate their base refs. The parent integrates isolated results after reviewing them. Do not cherry-pick or copy a result into a checkout where that result already exists.

Use fresh workers for independent tasks. Continue with the existing owner when the next step depends on its findings, edits, or running process. A context fork does not copy or isolate its filesystem state. Consolidate the current goal, corrections, and constraints in every steer or resume. Use the live lifecycle's nonblocking messaging and continuation calls, then process other reports while that owner works. Do not invent a background flag. Use supported completion waits shorter than 60 seconds, or a nonblocking status path when the schema cannot provide that wait. Inspect returned evidence and free completed workers when the host supports it. A mailbox wake or spawn acknowledgement is not a completed report. Before replacing a writer, stop or revoke its ownership and establish that it cannot continue writing the same files.

A worker's "done" is a claim. Review its actual diff and evidence. Use independent verification for high-risk changes or a disputed conclusion. Scale lanes to the distinct risks and the runtime's capacity. More agents and a different model are not substitutes for a better acceptance test.
